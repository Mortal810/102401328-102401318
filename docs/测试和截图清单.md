# 测试计划、手动走查与博客证据

## 一、自动单元测试

在项目根目录运行 `npm test`（Node.js 20+），共 20 个用例，测试源文件 `tests/core.test.js`。不上传虚假的通过截图；请在自己电脑上运行后截图实际输出。

- 输入检查：空名称、空联系方式、无效类型、未来日期、非法日期、描述超限。
- 正常路径：寻物/招领信息创建成功。
- 搜索路径：名称匹配、地点匹配、无匹配。
- 状态迁移：寻物已找到、招领已归还；非发布者、重复完成、无效 ID、演示记录禁止修改。
- 辅助分支：分类筛选、本机发布者筛选、HTML 特殊字符转义。

单元测试采用**白盒分支覆盖思路**：在 `core.js` 中找到条件判断，为进入正常分支和异常分支分别提供输入，并用 assert 检查输出和副作用。

## 二、必须手动操作的七条流程

| 编号 | 操作 | 预期 |
|---|---|---|
| M01 | 打开 Chrome → `index.html` → 全部/寻物/招领 | 显示卡片和相应筛选 |
| M02 | 首页→搜索→输入“耳机”→搜索结果→详情 | 匹配蓝牙耳机等数据，展示详情 |
| M03 | 搜索不存在的关键词 | 友好的“无结果”提示，可返回重新搜索 |
| M04 | 发布时不填写名称直接提交 | 拒绝发布、给出必填错误提示 |
| M05 | 完整填写寻物→发布成功→我的发布 | 本人刚发布的信息可以看到 |
| M06 | 本人将寻物标记“已找到”→回首页查看 | 多个视图均为“已找到”；重复更新不可用 |
| M07 | 完整填写招领→我的发布标记“已归还” | 详情与首页均变为“已归还” |

## 三、额外手动验收

1. 在详情页点击“复制联系方式”，粘贴到记事本验证。
2. 发布一条带照片的信息，进入详情检查图片展示。
3. 刷新页面，确认自发布记录及状态仍存在（仅当浏览器允许文件页面使用本地存储）。
4. 图片过大、日期在未来、无联系方式、搜索无结果等异常情形。
5. 缩小/放大 Chrome 窗口，检测布局、中文字体和内容是否遮挡。
6. **在真正评分机上或他人电脑上**仅用 Chrome 双击 HTML，再次执行 M01-M07。

## 四、博客证据建议

下面均由参与作业的同学**亲自在自己的电脑截图**，不可用预生成界面、虚构日志代替真实开发过程：

- 第一次 Figma 7 页面总览和原型链接；
- GitHub 主仓库创建、B 同学 Fork、feature 分支；
- 每次完成模块后不同的有意义 Commit；
- PR 页面、A Review 评论/Approve、Merge 后的记录；
- VS Code 项目目录树、README 展示、Chrome 直接打开 HTML；
- 首页/搜索/无结果/详情/联系方式复制/发布成功/我的发布；
- 同一条信息更新前的“寻找中”及更新后的“已找到”；招领对应“已归还”；
- 自己运行 `npm test` 的测试通过结果；
- 真实遇到的 Bug、排查过程、最终修复对比；
- 两位同学真实讨论/结对开发过程截图；
- PSP 实际用时填表和个人反思。

作业博客应在上述结果与过程真实完成后再撰写，尤其 GitHub Fork/PR/Commit 不能通过生成文件伪装。

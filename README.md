## 一、最快的运行方法（给助教和同学）

**无需安装 Node.js、无需 npm、无需网络、无需数据库、无需启动服务器。**

1. 下载仓库的 ZIP 或执行 `git clone`。
2. 解压后保持 `index.html`、`css/`、`js/`、`assets/` 目录的相对位置不变。
3. 使用最新版 **Google Chrome** 直接双击根目录 `index.html`（或右键“打开方式”→ Google Chrome）。
4. 首屏可浏览 8 条**演示记录**。点击“发布”可发布真实的本地记录；在“我的”页面可以将自己发布的记录标记为“已找到”或“已归还”。

**注意：**如果浏览器隐私设置禁止文件页面使用本地存储，页面会显示黄色提示。此时仍可在当前打开的页面体验业务流程，但刷新后新信息可能消失。建议在普通模式的最新 Chrome 中运行，开启站点本地存储。

## 三、7 个页面

1. 首页（浏览、类型切换、类别筛选）
2. 搜索（输入关键词、热门关键词）
3. 搜索结果（结果列表、无结果提示）
4. 信息详情（图片、信息、联系方式、复制、发布者完成状态）
5. 发布信息（寻物/招领、表单校验、可选图片）
6. 发布成功（返回首页、查看我的发布）
7. 我的发布（本地身份、统计、查看详情、更新状态）

完整业务路径：**发布信息 → 首页浏览或搜索 → 查看详情 → 联系发布者 → 发布者在“我的发布”更新状态**。

## 六、核心实现与限制

- **本地身份**：首次打开生成随机 `clientId`，存于 `localStorage`；每条新发布记录保存 `ownerId`，只有同一浏览器的同一标识才能通过界面结束该记录。这不是实名认证或真实服务端授权。
- **存储**：用户发布的记录保存在 `fzu-campus-lostfound-v1-items` 下；演示数据直接来自 `js/data.js`，不会写入用户发布数据。
- **隐私**：联系方式会在详情页面展示；如使用真实联系方式，请取得发布者本人同意，不要把真实的个人隐私数据随代码上传 GitHub。
- **照片**：最多 3 MB，客户端压缩后存到本地；Chrome 的 `localStorage` 有容量上限，大量照片可能导致保存失败，页面会给出提示。
- **离线运行**：运行时不使用 CDN，不 `fetch` 本地 JSON，不使用 ES Module，不依赖后端/跨域接口。
- **其他设备**：不同浏览器/设备无法看到当前机器发布的信息；清除浏览器站点数据会删除自建记录。如需多人共同在线使用，需要另行开发真实后端，不属于本次静态版要求。
